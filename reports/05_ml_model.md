# 05. ML 모델링

> 사용 스킬: `scikit-learn`(파이프라인, 누수 방지, 불균형 지표 선택), `mle-workflow` 원칙(재현성: 시드 고정, 피처 세트 저장)
> 코드: `src/s05_model.py` · 결과: `reports/05_model_results.csv`, `data/oof.parquet`, `data/test_pred_*.npy`

## 1. 실험 설계

| 항목 | 설정 | 이유 |
|---|---|---|
| 검증 | **5-fold Stratified K-Fold**, OOF(폴드 밖) 예측으로 평가 | test는 같은 기간·같은 작업지시에서 무작위로 뽑힘(test 작업지시의 99.99%가 train에 있음) |
| 강건성 점검 | **StratifiedGroupKFold(작업지시 단위)** | 처음 보는 작업지시에도 통하는지 확인 |
| 지표 | **PR-AUC**(주), ROC-AUC, F1 최적값과 그때의 정밀도·재현율 | 양성 5.8% 불균형 데이터. 정확도는 의미 없음(전부 정상이라 해도 94%) |
| 작업지시 타깃 인코딩 | 폴드 학습분으로만 계산. 학습분 자체에는 **내부 5-fold OOF**를 적용하고 사전확률로 평활(k=20) | 타깃 누수 방지 |
| 불균형 처리 | 로지스틱·RF는 class_weight, GBDT는 가중치 없이 **threshold 조정** | GBDT는 확률 보정을 유지하는 편이 F1 튜닝에 유리하다 |
| 피처 | `full` 167개 / `process_only`(시간·ID·작업지시 인코딩 제외) | |

## 3. 해석

1. **GBDT 3종과 RF는 사실상 동률이다**(PR-AUC 0.28 ~ 0.29). 모델 선택보다 **데이터 신호의 한계**가 성능을 결정한다. 실무 모델로는 가장 빠른 LightGBM, 보정이 가장 좋은 CatBoost가 후보다.
2. **PR-AUC 0.28은 무작위(0.058)의 약 4.9배**다. 최적 지점에서 불량으로 예측한 것 중 41%가 실제 불량(무작위 대비 7배)이고, 실제 불량의 22%를 잡는다.
   - 실무 의미: 전수 재검사 대신 **위험 점수 상위 3%만 재검사해도 불량의 21%를 미리 거를 수 있다.** 상위 1%만 보면 정밀도 86%다(8단계 검증).
3. **공정 변수만 써도 성능이 거의 유지된다**(0.284 → 0.282). 시간·작업지시 정보가 없어도 **공정 조건 자체에 예측 신호가 있다**는 뜻이다. 7단계 원인 해석은 이 모델로 진행한다.
4. **처음 보는 작업지시에서는 성능이 떨어진다**(PR-AUC 0.204). 신호의 일부가 "이 작업지시는 불량이 많다"는 **로트 효과**다. 신규 모델·신규 작업지시를 운영할 때는 성능 하락을 감안해야 한다. 그래도 무작위의 3.5배다.
5. **규칙 후처리 효과는 미미하다**(+0.001). 리드타임 2시간 초과·라인 혼입은 모델이 이미 학습했다. 다만 **설명 가능한 하드 규칙**이라 현장 운영에서는 별도 인터락으로 두는 것이 좋다.

## 4. 한계와 주의

- 최적 F1의 threshold는 OOF에서 고른 값이라 약간 낙관적이다. 운영 threshold는 **원하는 재검사 비율(예: 상위 3%)** 기준으로 정하는 것이 안정적이다.
- 하이퍼파라미터는 보수적인 기본값이다. 모델 간 차이가 작아 Optuna 탐색은 생략했다. 신호 한계 때문에 기대 이득은 +0.01 수준이다.
- test 제출용 예측(`data/test_pred_*.npy`)은 폴드 모델 5개의 평균이다.
